# Execute a migration without losing its end state

Inventory the units from current source, not an estimated file count. Mark each as pending, active, verified, deferred by the user or blocked by a named dependency. Keep one task record rather than separate competing plans.

Choose the riskiest complete path first. A service extraction unit includes routing, contract, caller, persisted state and the retirement condition; creating a new handler alone does not close it. Keep coupled contract/caller edits with one owner and isolate genuinely independent output paths.

For every unit record its entry revision, expected artifact, authorized check and recovery point. After a failed attempt, preserve the failure and revise the hypothesis before retrying. If a provider or operator step is unavailable, continue independent units while leaving that step visibly unverified.

Reconcile the final inventory with actual files and check receipts. Close only units whose artifacts exist and whose required evidence was obtained. Report remaining work in the requested end state, even if the local implementation is complete. A future-work paragraph cannot substitute for the user's requested migration.
