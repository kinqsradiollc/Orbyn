# Capture a lesson at the owner that can prevent it

Reconstruct the failed assumption, the observation that disproved it and the correction that worked. Ask whether the evidence supports a reusable rule or only one local circumstance. Use current-task artifacts rather than searching unrelated conversation history.

Locate the canonical writable owner before editing. Installed plugin caches and generated host links are not authoring targets. Put company-only behavior in the consumer namespace and shared improvements in an explicitly authorized public contribution.

Choose the narrowest durable enforcement: a representation that excludes an invalid state, an existing validation rule, or a focused instruction when judgment is unavoidable. For a failed pin update, guard the expected baseline and managed-file hashes; another universal “be careful” paragraph will not prevent the race.

Return the changed owner, the evidence behind the lesson and a nearby situation where it does not apply. Preserve historical notices and failed receipts. Do not add personal memory, external messages or a mandatory review panel as a side effect.
