# Design a boundary that callers can use

Begin with one real caller and a failure it must handle. Write the proposed call and result before drawing directories. Inventory the current owner of identity, mutable state, effects and cleanup; a new interface must take responsibility away from callers rather than merely rename their parameters.

For each alternative, follow one normal operation and one interrupted operation through those owners. Compare the number of independent decisions callers must repeat, compatibility with released consumers and the cost of recovery. Select a design when that evidence resolves the consequential choice. If a measurement is needed, give the smallest prototype a decision threshold and disposable inputs.

Produce an owner/interface table, a representative call, state transitions, the rejected alternative and a migration order. Keep domain ownership separate from platform rendering. A task editor can share the update contract while web and mobile retain their own focus and navigation behavior.

Check the proposed interface against a stale write, revoked access and a retry after an unknown result where those cases apply. A design-only task returns this contract; it does not reorganize files. Implementation checks belong to the resulting change, within the user's scope.
