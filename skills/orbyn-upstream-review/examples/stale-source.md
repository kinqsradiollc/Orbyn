# Worked example: an old source pin while offline

Synthetic request: a project adapted an external review helper at commit A. It
also has company-only release guidance and an ignored source snapshot at commit
B. The user asks whether to update; the agent has no network.

Read the actual adaptation, both local snapshots and their license/source
records. Compare A to B and map relevant changes to the existing helper owner.
Label B as the latest locally available source, not the current upstream head.
Keep company guidance under its existing `project-skills/` namespace and raw
snapshots under ignored `orbyn-references/`. Verify the index contains neither
research root. Do not run the downloaded helper to understand its text.

If B fixes an applicable handling error, propose a scoped adaptation with its
evidence and required caller/behavior checks. A review-only request does not
authorize rewriting the helper, a public contribution or changing either pin.
If an update is authorized later, change the canonical owner rather than an
installed cache and record which source change was adopted. Advance the public
consumer pin only to an actual reviewed revision with matching managed bytes.

Failure: call B “latest,” bump the import revision without replacing or verifying
source files, copy a company release procedure into public source, and report
source inspection as a passing runtime or live model evaluation.
