# Prototype an uncertainty

Use the parent [workflow](../SKILL.md). Freeze one empirical question, its hard
constraints and the observation that will select or reject an approach. First
check whether current source or primary documentation already settles it.

Build only the uncertain seam with disposable data and a separate output path.
Keep the reference/default candidate and relevant environment comparable. For a
storage choice, measure the actual access pattern and failure/recovery need;
a synthetic insert loop cannot settle the whole application's storage decision.

Inspect the result, failed cases and confounders before selecting an option.
An inconclusive observation remains inconclusive. Retain the question, candidate,
inputs, raw outcomes and limitation in one short decision record. Remove or retain
owned artifacts intentionally without deleting someone else's output.

Return the answer and hand it to [architect](../../architect/SKILL.md) or
[stack selection](../../orbyn-stack-selection/SKILL.md). A prototype is not
production code, a deployment or permission to install external services.

For UI exploration, use the [preview method](../../orbyn-ui-design/references/prototypes.md)
to deliver an app route/story or portable HTML, meaningful interactive states and
a verified opening path. For all prototypes, name stored artifacts, owned running
resources and their retention/cleanup condition under
[artifact lifecycle](../references/artifact-lifecycle.md). An empirical backend
prototype needs its measured decision and reproducible inputs; a requested human
UI preview also needs an artifact the person can open and exercise.
