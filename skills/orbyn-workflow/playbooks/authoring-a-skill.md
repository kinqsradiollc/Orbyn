# Authoring a skill

Use [orbyn-skill-creator](../../orbyn-skill-creator/SKILL.md). Check the existing
owning skill, stack, catalog, host links and documentation before adding another
entrypoint. Classify library versus company/repo ownership before editing.
Follow the [consumer boundary](../../orbyn-setup/references/project-skills.md) for
local skills and migration; public catalog registration applies only to shared
library skills. Keep needed guidance available under the
[offline contract](../../orbyn-setup/references/offline.md).

For substantial changes, the lead defines the routing contract and delegates
owned skill files under the parent [workflow](../SKILL.md). The lead reviews the
instructions and downstream handoff, then performs authorized static metadata,
link and catalog checks. Children author their assigned content directly. A live
model trial or product test needs its own applicable authorization.
