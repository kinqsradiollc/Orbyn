# Turn a preference into a scoped rule

Separate an explicit enduring preference from a task constraint and your own inference. Use only records selected by the user. Write a positive example and a nearby case where the rule should stay inactive before choosing its owner.

Find the existing owner: repository policy for a shared workflow, a consumer-owned skill for company behavior, or an explicitly requested personal skill. Public library contribution is a separate scope decision. Preserve existing notices and settings; saving a preference does not authorize changing memory, global configuration or recurring tasks.

For “inspect exported PDFs,” encode the export artifact, the inspection step and what to report if the viewer is unavailable. Do not broaden it into an application-build requirement for every document edit. Keep the rule beside the exporter rather than in three unrelated prompts.

Return the exact changed owner, the recorded preference, its non-trigger example and checks actually performed. If the user only asks for advice, return the proposed rule without writing it.
