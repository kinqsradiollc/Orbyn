## Existing Orbyn comparison

- `desktop/src/app/App.tsx:188–275` already creates one shared planner and two independently scoped workspace controllers, uses focus/pointer capture to choose the command owner and returns focus to the primary container on close. `App.tsx:1524–1579` guards pane closure around open edits and assistant drafts. Preserve these boundaries; Macro is inspiration for clearer pane lifecycle/focus, not a reason to replace React or duplicate the shared planner.
- `desktop/src/app/workspace.css:252–262,306–343` uses equal columns, a 1279px viewport fallback and `display:none` for the inactive pane. That hides ordinary controls from rendering, but JS autofocus/global listeners can still run in mounted controllers. An explicit visible-pane command/focus contract is useful even when CSS hides the pane. This is a risk inference, not a reproduced bug.
- `desktop/src/components/SidebarResizer.tsx:15–49,60–105` already provides bounded measured resizing, pointer cancellation, keyboard steps and remembered width. Keep Orbyn's rollback and accessible numeric values. Macro's solver is relevant only if independently resizable working panes become requested; do not add arbitrary multi-pane infrastructure now.
- `desktop/src/features/docs/docs.css:95,4736–4760` already uses a document container query; `DocEditor.tsx:2638–2657` bounds a floating toolbar to its page and observes page resizing. `DocSourcePreview.tsx:106,287–326,433–434` has split/source/preview modes and guarded reciprocal scroll synchronization. Apply the same actual-pane-width approach to source tools and secondary panels before adding another global viewport breakpoint.
- `desktop/src/hooks/useModalFocus.ts:21–52,77–85` already excludes hidden/inert controls, allows explicitly owned pickers, defers to higher dialogs and restores the opener. `desktop/src/lib/dialogLayers.ts:14–38` resolves ownership through layer and paint order. Keep this established contract and improve explicit pane ownership around it.
- `mobile/src/hooks/usePaneWidth.ts:4–12` measures the actual pane with a window-width fallback. Reuse that for mobile secondary-panel composition; do not infer native drawer/back behavior from web source.
- ADR 003 `docs/adr/003-product-ui-ux-redesign.md:107–115,120–145` requires independent paired-pane work, one visible secondary panel when narrow, all three document modes, hideable source and accessible resizable navigation. These are already owner requirements; this report supplies implementation patterns and checks without changing their scope.

## Recommended ADR wording for parent

“Macro source informs explicit pane ownership, stable content lifetime, actual-pane-width adaptation and measured priority collapse. Keep Orbyn's shared planner and pane-scoped controllers; hidden panes retain work while yielding focus and shortcuts. Navigation/search target the focused visible pane, and temporary dialogs own input until dismissal. Reuse these mechanisms within existing React/Expo and semantic tokens; reference source inspection is not rendered or native acceptance evidence.”

No source was imported. Any later direct code/dependency reuse requires license review. Do not wholesale adopt Macro's Solid/Kobalte orchestration, permanent icon-only rail, automatic provider fallback, glass chrome, arbitrary split count, hardcoded 400px pane rule or animation policy. The proposed benefits remain inference until Orbyn's complete candidate is exercised.

source/preview buffers, retaining the requested Split preference for expansion.

controls and directional pan share one optional disclosure; source edits update
request IDs while preserving zoom and disclosure state. Export callbacks reject
old request errors. ADR 003 records stable presentation lifetime and constrained
source switching. Full dialog scroll composition, pan retention, focus recovery
and rendered short/narrow behavior still need complete-candidate qualification.
